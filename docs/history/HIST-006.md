## HIST-006 — релиз зависел от удалённого checkout на сервере

**Дата:** 2026-11-01

**Контекст:** Перевод `backery` с локальной сборки PHP на готовый образ GHCR.
После успешного image-only релиза старый каталог `/root/bakery-orders` и
контейнеры были удалены.

**Симптом:** HTTPS `/health` сначала был недоступен, затем Caddy отдавал 502.
PHP и PostgreSQL-контейнеры отсутствовали, хотя постоянные тома
`laravel-app_postgres_data` и `laravel-app_caddy_data` сохранились.

**Причина:** прежний deploy-скрипт вызывал Compose-файлы и `.env` из
`/root/bakery-orders` и проверял уже запущенный PostgreSQL-контейнер до
обновления. После удаления каталога и контейнеров такой релиз не мог
восстановить сервис. Caddy отдельно был поднят без PHP и отдавал 502.

**Фикс:** минимальный `/opt/bakery/compose.yml` содержит Caddy, PHP и
PostgreSQL с готовыми образами, без `build` и bind-монтажа исходников.
Переменные приходят из GitHub Environment через ограниченную SSH-команду,
постоянный `.env` на хосте не создаётся. Скрипт проверяет существование
внешних томов, делает pull/tag, запускает весь Compose с `--no-build --wait`,
проверяет HTTPS и очищает старый образ. Проверено на коммите `a550ba6` после
удаления контейнеров: три сервиса running, PHP и PostgreSQL healthy,
HTTPS `/health` 200, CSS совпадает с образом, в БД 75 пользователей,
220 заказов и 17 сессий. Пользователь подтвердил успешный вход.

**Паттерн для checklist:** после удаления checkout/контейнеров релиз не может
восстановить сайт → проверить, не зависит ли Compose от исходников и `.env`
на хосте и не требует ли скрипт уже работающий контейнер.
