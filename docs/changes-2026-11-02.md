Документ фиксирует реализованные компоненты, известные ограничения и области регрессионного тестирования. **Наличие кода в `main` или PR не означает, что CI, ручная приёмка и production подтверждены.** Для точного текущего статуса см. ## Административный интерфейс

- **PR #3:** навигация администратора переведена в боковую панель на десктопе; на узких экранах — горизонтальная прокрутка. Точечный фон убран.
- **PR #4:** выравнивание фильтров аналитики, даты склада и чекбокса нерабочих дат; формы адаптированы к малой ширине.
- **PR #5:** логотип и выход разнесены по краям шапки, выбор состава групп переведён из чрезмерно плотной сетки в карточки, увеличены поля справочников и выровнены кнопки аккаунтов.
- Необходимо проверять доступность подписей, табуляцию, горизонтальную прокрутку широких таблиц, печатную версию и отсутствие влияния на кабинет магазина.
- CSS остаётся монолитным `public/bakery.css`; дополнительные правила переопределяют прежние. При последующем рефакторинге объединять дубликаты осторожно.

## BAK-16 — персональные скидки

- Для каждой торговой точки доступно необязательное числовое поле «Скидка, %». Пустое / нулевое значение означает отсутствие скидки.
- Миграция создаёт `bakeries.discount_enabled` и `bakeries.discount_percent`; начальная скидка 10% для точки «СНТ Надежда» определяется по названию/адресу. **До применения миграции проверить, что фильтр выбирает только нужную точку.**
- При использовании общего прайса скидка применяется **к конкретной точке после определения источника цены**; другие точки с тем же прайсом не наследуют скидку.
- Расчёт цены одной единицы товара ведётся в целых копейках с округлением половины копейки вверх: `intdiv(baseKopecks * (100 - percent) + 50, 100)`. Затем цена единицы умножается на количество.
- Базовые цены редактируются без скидки, чтобы сохранение прайса не применяло её повторно.
- Новые заказы сохраняют рассчитанную цену каждой позиции; существующие заказы не пересчитываются при изменении процента. Возвраты, накладные, XLSX и аналитика должны опираться на сохранённые суммы.
- Пограничные случаи: пустое значение; 0%, 10%, 50%, 100%; округление 0,5 копейки; два магазина с общим прайсом и разными скидками; изменение скидки после создания заказа; возврат после изменения скидки; создание/редактирование магазина без доступа пользователя.

## Групповые накладные — Балтийская и Колпино

- **PR #7:** для сводных групп с названиями, содержащими «Балтийск» или «Колпино», в HTML и XLSX скрываются самостоятельные столбцы возвратов. Данные возвратов остаются в расчётах, выводимая сумма к оплате учитывает их.
- Печатные сводные формы **не прибавляются** к общему итогу заказов: заказы участников уже учтены в индивидуальных накладных.
- **PR #8:** блок «Состав группы на момент формирования» в XLSX получил заголовки колонок, границы, стили итогов и отдельный итог по точкам.
- Для этих групп нижний блок показывает «Торговая точка», «Изделий, шт.», «Заказ, ₽», «К оплате, ₽», но не «Возврат». Для остальных групп колонка возврата сохраняется.
- Количество изделий относится к заказанным штукам, денежные суммы указаны в рублях, а исходный расчёт ведётся в копейках.
- Группировка определяется именем группы, а не постоянным идентификатором. Это технический риск при переименовании и похожих названиях; долгосрочное решение — явная настройка формата в базе.
- Текущая группировка товаров по `product_id:unit_kopecks` сохраняет различие цен на один товар внутри разных точек.

## Контрольные проверки

| Область | Регрессия |
| --- | --- |
| Десктоп/мобильный UI | Меню не перекрывает содержимое, формы не слипаются, кнопки одинаковой высоты, чекбоксы рядом с подписями |
| Скидки | Настройки точек изолированы, цена округляется в копейках, общий прайс не изменяется |
| Заказ | Quote/hash учитывают скидку, сохранённая цена совпадает с подтверждением |
| Возвраты | Используются цены позиции заказа, не новый прайс |
| Группы | Балтийская/Колпино скрывают возвраты только визуально, остальные показывают их |
| XLSX | Есть заголовки, стили, единицы измерения, итоги, нет лишних возвратных столбцов |
| Аналитика | Суммы совпадают с сохранёнными заказами и возвратами |
| Безопасность | Магазин не получает доступ к чужим ценам |

## Проверка изменений

```bash
composer pre-commit
composer pre-push
php artisan test --filter=StoreDiscountTest
php artisan test --filter=GroupWorkbookLayoutTest
php vendor/bin/phpstan analyse --memory-limit=512M
```

Эти команды — **план проверок**, а не утверждение, что они уже выполнены. CI, локальные тесты и ручные проверки должны быть отмечены отдельно в [state.md](state.md). Регрессионные тесты не заменяют открытие реальных XLSX в Excel/LibreOffice на этапе приёмки.
