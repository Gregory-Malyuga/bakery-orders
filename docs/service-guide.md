# Сервис заказов пекарни: страницы и функции

Этот документ описывает реализованное поведение **текущего кода репозитория**. Данные, настройки времени приёма и доступность конкретных магазинов зависят от базы установленного экземпляра. Документ не подтверждает состояние рабочего сервера. Основные источники: `routes/web.php`, `routes/api.php`, контроллеры `app/Domains/Bakery/Presentation/Http/Controllers`, классы `app/Domains/Bakery/Application` и шаблоны `resources/views/bakery`.

## Для кого предназначен сервис

Есть две веб-роли. **Магазин** оформляет заказ на завтрашнюю поставку и видит свою историю. **Администратор пекарни** видит принятые заказы, планирует выпуск, ведёт справочники, меняет заявки, фиксирует возвраты и получает печатные формы и отчёты. Принадлежность к роли и активный статус проверяются на сервере; прямой ввод URL не даёт доступ к чужим разделам. Публичной регистрации нет.

Корень `/` отправляет гостя на `/login`, администратора на `/admin`, магазин на `/orders`. Вход — почта и пароль. Выход завершает сессию. Администратор может временно войти как активный пользователь магазина из вкладки аккаунтов и затем вернуться к своей сессии. Эти действия записываются в журнал приложения.

`/admin` без параметров открывает заказы на **завтрашнюю** дату по Москве. Отчёт без параметров показывает период с начала текущего месяца по сегодняшний день. На главной странице магазина дата поставки тоже всегда завтра.

## Сценарий магазина

1. Администратор создаёт аккаунт и назначает ему один или несколько магазинов. Один магазин нельзя привязать к двум аккаунтам. При отсутствии привязки кабинет сообщает об этом и не предлагает форму заказа. Деактивированный магазин недоступен для оформления.
2. Магазин выбирает свою точку, если их несколько. Для каждой точки допускается **один принятый заказ на дату поставки**. История хранит принятые и отменённые заказы; интерфейс выводит последние 30. После отмены можно оформить новый заказ на ту же дату, пока приём открыт.
3. Форма показывает активные товары, цену за штуку и минимум. Если цена не задана или товар исключён из ассортимента точки, поле количества отключено. Количество `0` означает «не заказывать», нужен хотя бы один товар с положительным количеством. Каждое значение — целое от 0 до 100000.
4. Минимум может быть общим для товара или индивидуальным для магазина. Тип фасовки дополнительно ограничивает число штук: `single` — любое положительное; `pair` — только чётное; `mixed` — число, складывающееся из пакетов по 3 и 5 (например, 3, 5, 6, 8; 4 и 7 нельзя). Можно добавить комментарий до 1000 символов.
5. Кнопка «Проверить заказ» открывает второй шаг с точной суммой. «Изменить количество» возвращает форму с уже введёнными значениями. «Подтвердить заказ» повторно проверяет доступность, цену, количество и время. Если расчёт изменился, показывается новый вариант для повторного подтверждения. Повторная отправка одного запроса не создаёт дубликат.
6. После подтверждения видна карточка заказа. Позиции содержат название и цену на момент оформления. Отмена доступна только для принятого заказа **до времени отсечки в день оформления по Москве**. Отменённый заказ остаётся в истории и не входит в сводку, печать и отчёт принятых заказов. Старый заказ можно «Повторить»: копируются только ещё активные и доступные для точки товары; цены и правила проверяются заново.

Время отсечки хранится в настройках, начальное значение — **18:30 МСК**. Ровно в минуту отсечки приём закрыт; следующий заказ на завтрашнюю поставку откроется в 00:00 МСК. Проверка выполняется на сервере на предварительном и финальном шагах, время устройства магазина на неё не влияет.

## Сценарий пекарни: заказы и производство

Вкладки «Заказы», «Выпуск», «Фасовка», «Наклейки» и «Заготовки» используют одну выбранную дату поставки и только принятые заказы. «Ещё не заказали» сравнивает принятые заказы с активными магазинами. Таблица заказов разбита по 20 строк.

«Выпуск» суммирует заказанные штуки по товарам и показывает распределение по магазинам. «Фасовка» сначала рассчитывает пакеты **для каждой точки отдельно**, затем складывает результаты по товару; пакеты между магазинами не объединяются. «Наклейки» считает один экземпляр на каждый рассчитанный пакет. «Заготовки» умножают заказанные количества на нормы изделий и теста из раздела рецептур. Если для изделия нет полной нормы начинки, экран сообщает его название. Складские остатки в расчёте не участвуют.

Карточка принятого заказа позволяет изменить заявку: увеличить, уменьшить или обнулить старую позицию и добавить доступный товар. Нельзя оставить заказ без позиций. Причина обязательна; каждое изменение фиксирует состав и сумму до и после. Для прежней позиции сохраняется цена заказа, для новой берётся текущая цена магазина. Фасовка проверяется снова. Корректировка сразу отражается в сводке, отчёте и накладной. Отдельное примечание пекарни можно сохранить в заказе; оно показано в административной карточке.

Возврат записывается в карточке принятого заказа с товаром, количеством и необязательной причиной. Можно вернуть товар, которого нет в составе заказа, если он активен и доступен магазину. Для заказанной позиции берётся сохранённая цена, для прочего доступного товара — текущая цена; она фиксируется в записи возврата. Возврат уменьшает финансовый итог после возвратов, **не уменьшает число изделий к выпуску или расход сырья**. В коде нет ограничения возврата заказанным количеством: сумма после возвратов может стать отрицательной.

## Справочники, аккаунты и рецептуры

- **Магазины:** название и адрес используются при создании снимка заказа. Деактивация запрещает новые заказы, но не удаляет старые. Удаления магазина через веб-интерфейс нет.
- **Товары:** задаются имя, порядок отображения, активность, общий минимум и фасовка. При сохранении минимум поднимается до допустимого для фасовки (1, 2 или 3). Деактивация скрывает товар из новой формы заказа; история остаётся. Удаления товара через веб-интерфейс нет.
- **Цены и ассортимент:** цена задаётся отдельно для пары магазин–товар; отсутствие цены означает невозможность заказа. Доступность можно выключить независимо от цены. Чтобы включить товар, сначала надо назначить цену. Пустое поле индивидуального минимума возвращает общий минимум. При нескольких магазинах у одного аккаунта прайс общий: источником служит первый выбранный магазин, изменение цены меняет общий прайс. Исключения из ассортимента и индивидуальные минимумы остаются у каждого магазина свои.
- **Аккаунты:** логин — почта; пароль нового аккаунта обязателен и должен быть не короче 10 символов. При правке пустое поле пароля сохраняет старый. Можно отвязать все магазины, сменить почту и активность. Неактивный пользователь войти не может. На экране не предусмотрены удаление аккаунта и восстановление пароля через письмо. «Войти как пользователь» доступно для активного аккаунта; на экране магазина появляется возврат к сессии администратора.
- **Настройки:** время окончания приёма и отмены вводится в формате `ЧЧ:ММ` и действует сразу. Других настроек в этой вкладке нет.
- **Ингредиенты:** единицы `г`, `шт.`, `ст. л.` закрепляются при создании. Название можно изменить; оно обновится в рецептурах и расчётах через общий каталог. Скрытый ингредиент нельзя выбрать для новой строки, но существующие строки продолжают участвовать в расходе. Изменения единицы и удаления ингредиента через веб-интерфейс нет.
- **Рецептуры:** для изделия задаются тип теста (`основное`, `самса`, `без теста`), вес основного теста на штуку и ингредиенты с количеством. Для двух видов теста задаются размер замеса и ингредиенты в граммах. Ингредиенты выбираются из общего справочника, повтор одного ингредиента в рецепте запрещён. «Вернуть исходную рецептуру/нормы» удаляет ручную поправку и восстанавливает встроенные нормы из исходной таблицы. Новые значения сразу используются в заготовках и отчёте за период; исторического снимка рецептуры в заказе нет.

## Печать, Excel и отчёт

Одна или все накладные за дату открываются как печатная HTML-страница с кнопкой браузерной печати. В Excel для каждой накладной создаётся отдельный лист; общий файл также содержит матрицу «Заказ» по магазинам и итоги. Если возвраты есть, печатная форма и Excel показывают их рядом с заказом и итог после возвратов. Отменённые заказы исключены. Отдельные файлы доступны по `/admin/orders/{order}/xlsx` и `/admin/xlsx?date=…`; HTML по `/admin/orders/{order}/print` и `/admin/print?date=…`.

Отчёт `/admin/report` выбирает **даты поставки** включительно. Показывает заказанную сумму, сумму возвратов, разницу, изделия и расчёт расхода сырья. Excel `/admin/report/xlsx?from=…&to=…` содержит листы «Заказы», «Изделия», «Сырьё». Текущие рецептуры применяются и к старому периоду; отчёт не хранит историческую норму сырья. Возврат товара вне заказа выводится отдельной строкой с нулём заказанного количества и отрицательной разницей. Остатки и закупки сырья не учитываются.

## API и служебные команды

В репозитории есть **отдельный базовый API пользователей**, не API заказов пекарни: `POST /api/auth/login`, `POST /api/auth/logout` и `GET/POST /api/v1/users`, `GET/PUT/PATCH/DELETE /api/v1/users/{user}`. Вход возвращает токен Sanctum; операции пользователей требуют токен, подтверждённый статус и проверку доступа. Роль магазина не допускается к этому legacy API. Он не создаёт и не редактирует заказы, возвраты, рецептуры или цены. Swagger UI настроен на `/api/docs`, схема — на `/api/docs.json`; это документация базового API, а не веб-панели пекарни. `GET /health` проверяет БД; `/up` — штатный маршрут здоровья Laravel.

Операторские команды не являются страницами:

| Команда | Назначение |
| --- | --- |
| `php artisan bakery:create-admin EMAIL` | Интерактивное создание администратора со скрытым вводом пароля. |
| `php artisan bakery:seed-reference FILE [--dry-run]` | Загрузка закрытого исходного XLSX каталога, магазинов, цен и аккаунтов; режим проверки без записи. |
| `php artisan bakery:import-catalog CSV [--apply]` | Проверка согласованного CSV и применение только с `--apply`. |
| `php artisan db:seed --class=BakeryDemoSeeder` | Локальные демоданные; не команда для рабочего окружения. |

Подробности первого запуска, формата CSV, резервной копии и контейнеров — в [README](../README.md). Команды импорта не являются функцией загрузки файла в веб-интерфейсе.

## Чего в текущем сервисе нет

Этот список означает отсутствие реализации в текущих маршрутах и интерфейсе, а не запрет на развитие сервиса:

- публичной регистрации и самостоятельного восстановления пароля;
- заказа на произвольную дату, планирования нескольких дат одним магазином или редактирования магазином уже принятого заказа (магазин может отменить его в допустимое время и оформить снова);
- нескольких одновременно принятых заказов одной точки на одну дату;
- веб-загрузки XLSX/CSV каталога, удаления магазинов, товаров, аккаунтов или ингредиентов;
- отдельного экрана складских остатков, закупок, списания сырья и учёта фактического выпуска; заготовки — расчётная потребность по заказам и нормам;
- ограничителя возврата числом заказанных штук, согласования возврата магазином и отдельной складской операции возврата;
