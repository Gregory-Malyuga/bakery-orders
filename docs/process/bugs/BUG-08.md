# BUG-08 — клиенты теряют web-сессию после релиза

**Статус:** открыт

**Приоритет:** P1

**Дата обнаружения:** 2026-11-01

**Связанная задача:** BAK-13

## Наблюдение

- Со слов пользователя, после перезагрузки Docker Compose при релизе клиентам приходится входить заново.
- Воспроизведение: войти в рабочем браузере, выполнить обычный релиз с перезапуском Compose, открыть `/orders`.
- Ожидалось: вход сохраняется в пределах срока жизни сессии.
- Получилось: у клиентов пропадает авторизация. Точный релиз, время и число затронутых клиентов не установлены.
- Влияние: магазины вынуждены повторять вход; заказы и пароли, по имеющимся сведениям, не теряются.

## Диагностика

- Текущий Compose принудительно задаёт `SESSION_DRIVER=database`; миграция создаёт таблицу `sessions`, а PostgreSQL использует постоянный том. API уже использует Sanctum и таблицу `personal_access_tokens`.
- Прежний production Compose также задавал `SESSION_DRIVER=database`. Поэтому смена способа авторизации или добавление Redis без проверки рабочего окружения не объясняют симптом.
- Проверить на рабочем хосте фактический Compose-проект, постоянство `APP_KEY`, наличие тома и строки сессии до и после релиза, время последней активности и срок `SESSION_LIFETIME`. Не выводить значения ключа и cookie в журналы.
- На рабочем хосте `backery` 2026-11-01 запущен старый код `565a885` с Compose из трёх файлов. PHP использует `database`, в `sessions` есть 8 строк, `APP_KEY` из `.env` и контейнера совпадает. Реальный срок неактивности — 120 минут; активны за последние 120 минут 3 из 8 сессий. `.env` не содержит `SESSION_LIFETIME`, поэтому действует этот короткий срок. Это подтверждённая причина истечения сессий после двух часов бездействия, но не доказывает потерю ещё активной сессии непосредственно при перезапуске.

## Исправление и приёмка

- В репозитории добавлен регрессионный тест хранения web-сессии в БД при повторном создании сервисов сессии и авторизации; он требует запуска в тестовой PostgreSQL. Срок неактивности по умолчанию в Laravel увеличен до 30 дней.
- Инструкция релиза закрепляет постоянство `APP_KEY`, Compose-проекта и тома PostgreSQL.
- Приёмка: тест и полный CI проходят; на рабочем хосте браузер тестового магазина остаётся авторизованным после `docker compose up -d --build --remove-orphans` с тем же `.env`, а строка `sessions` сохраняется. Отдельно проверить повторный релиз и срок неактивности.
