# BAK-15 — подготовка репозитория к публичному доступу

**Статус:** в работе. **Приоритет:** P1.

Удалить из публикуемой истории два исходных XLSX с данными магазинов и цен и исторический фиксированный `APP_KEY` локального Compose. В актуальном дереве источник начальной загрузки должен передаваться команде явно, без хранения файла в Git. Начальный пароль новых магазинных аккаунтов вводится скрыто и не содержится в коде.

## Критерии приёмки

- [ ] В публикуемой истории нет XLSX-файлов и исторического фиксированного ключа Compose.
- [x] Команда `bakery:seed-reference` принимает внешний XLSX, режим `--dry-run` сохраняется.
- [x] Исходные XLSX и локальные временные копии исключены из Git и Docker build context.
- [x] Тестовые файлы и `.github/workflows/ci.yml` не изменены; CI проходит на очищенной истории (run `41281724330`).
- [ ] Перед публикацией проверены удалённые ветки и теги; после обновления `main` проверено состояние удалённой истории.

Переписывание истории меняет SHA всех затронутых коммитов. Старые локальные клоны и worktree потребуется пересоздать или вручную синхронизировать с новой историей. Рабочие секреты GitHub Environment не входят в Git; их значения здесь не фиксируются.

После force push `main` (`9abe7b3` → `acb636c`) обе закрытые PR-ссылки остались. Отдельная проверка `refs/pull/2/head` по Git SSH вернула два XLSX в достижимой истории; GitHub API также вернул старый коммит `9abe7b3`, а Git fetch скачал его по SHA. До публичного доступа нужно обратиться в GitHub Support для удаления PR-ссылок и кэшированных представлений, затем повторить проверку доступа к старому SHA и XLSX. Существующий workflow на `acb636c` прошёл полностью, включая production deploy.
