# BAK-14 — image-only релиз на backery

**Статус:** выполнено. **Приоритет:** P1.

После успешных тестов, сканирования образа и публикации `latest` GitHub Actions
должен взять deploy-скрипт, Compose и Caddyfile из текущего коммита, передать
их на `backery` через SSH stdin и выполнить:

1. `docker pull` образа GHCR с тегом SHA текущего коммита;
2. `docker tag` этого образа в существующий рабочий тег
   `laravel-app-php:latest`;
3. `docker compose up -d --no-build --wait` в проекте `laravel-app`, поднимая
   PostgreSQL, PHP и Caddy при их отсутствии;
4. проверить подключение прежнего тома PostgreSQL и выполнить
   `docker compose exec -T php php artisan migrate --force --no-interaction`;
5. проверить HTTPS `/health`, затем удалить временный SHA-тег и прежний образ,
   если он больше не используется.

После удаления старого checkout и контейнеров прежняя реализация не могла
восстановить сервис: Compose и `.env` исчезли, HTTPS `/health` отдавал 502.
Источником кода релиза служит checkout GitHub Actions. На хосте ограниченный
SSH-ключ запускает системный `python3 -`; код и Compose/Caddyfile из коммита
сохраняются в `/home/bakery-deploy/releases/<SHA>/`. Ручная установка
deploy-скрипта на сервер больше не используется. В Compose три сервиса с
готовыми образами, поле `build` отсутствует. Runtime-переменные GitHub
Environment передаются через SSH stdin и используются только при релизе.
`.env` на сервере не создаётся. Существующие тома PostgreSQL и сертификатов помечены
`external: true`, поэтому отсутствие тома останавливает релиз вместо создания
пустой БД. Команда `up --no-build --wait` запускает все три сервиса даже после
удаления контейнеров. Миграции запускаются из нового PHP-контейнера после
проверки тома; ошибка миграции прерывает релиз до проверки `/health` и очистки
образов. На хосте `git fetch/checkout` и `down -v` не выполняются. Доступ
`bakery-deploy` к Docker даёт этому CI-ключу привилегии хоста, поэтому ключ
ограничен GitHub Environment и SSH-опцией `restrict`.

Caddy проксирует все запросы в PHP-контейнер, чтобы `bakery.css` брался из
нового образа. Конфигурация Caddy приходит из `deploy/Caddyfile` того же коммита.

## Критерии приёмки

- [x] В `production` доступны секреты `DEPLOY_SSH_PRIVATE_KEY_B64` и
  `DEPLOY_KNOWN_HOSTS`.
- [x] CI после build, Trivy, smoke и публикации `latest` запускает deploy job.
- [x] На хосте PHP-контейнер запущен из образа с SHA релиза и `/health` отвечает.
- [x] `bakery.css` после релиза соответствует содержимому образа.
- [x] `laravel-app_postgres_data` остаётся подключённым к PostgreSQL;
  в БД доступны 75 пользователей, 220 заказов и 17 сессий, `/login` отвечает 200.
  Пользователь подтвердил успешный вход после восстановления.
- [x] Старый неиспользуемый PHP-образ удалён либо зафиксирована причина, по
  которой Docker оставил его.
- [x] Deploy job завершается успешно с автоматической очисткой образов после
  ожидания готовности PHP.
- [x] Релиз поднимает все сервисы из `/opt/bakery` после удаления контейнеров;
  на хосте нет checkout и `.env`.

Перед изменением релиза 2026-11-01 сделан проверенный `pg_dump -Fc`:
`/root/bakery-backups/bakery-20261101T052048Z.dump` на хосте и копия
`C:\Users\user\AppData\Local\Temp\bakery-20261101T052048Z.dump` на этом ПК;
SHA-256 обеих копий совпадает. `pg_restore -l` прошёл; пробное восстановление
ещё не выполнялось.

Для повторного восстановления без нового коммита workflow `CI/CD` можно
запустить вручную из GitHub Actions на ветке `main` (`Run workflow`). Docker
автоматически перезапускает существующие контейнеры после рестарта хоста
благодаря `restart: unless-stopped`.
