# BAK-14 — image-only релиз на backery

**Статус:** в работе. **Приоритет:** P1.

После успешных тестов, сканирования образа и публикации `latest` GitHub Actions
должен подключиться к `backery` ограниченным ключом и выполнить:

1. `docker pull` образа GHCR с тегом SHA текущего коммита;
2. `docker tag` этого образа в существующий рабочий тег
   `laravel-app-php:latest`;
3. `docker compose up -d --no-build --no-deps --force-recreate php` в текущем
   проекте `laravel-app`;
4. удалить временный SHA-тег и прежний образ, если он больше не используется.

После удаления старого checkout и контейнеров прежняя реализация не могла
восстановить сервис: Compose и `.env` исчезли, HTTPS `/health` отдавал 502.
Новый источник запуска — `/opt/bakery/compose.yml` и `/opt/bakery/Caddyfile`.
В нём три сервиса с готовыми образами, поле `build` отсутствует. Runtime
переменные GitHub Environment передаются ограниченной команде релиза через
SSH stdin и используются только в процессе `docker compose up`. `.env` на
сервере не создаётся. Существующие тома PostgreSQL и сертификатов помечены
`external: true`, поэтому отсутствие тома останавливает релиз вместо создания
пустой БД. Команда `up --no-build --wait` запускает все три сервиса даже после
удаления контейнеров. Git fetch/checkout, миграции и `down -v` не выполняются.

Перед первым релизом Caddy один раз переведён на проксирование всех запросов
в PHP-контейнер, чтобы `bakery.css` брался из нового образа. Старый Caddyfile
сохранён на хосте как `Caddyfile.domain.before-image-release-20261101`.

## Критерии приёмки

- [x] В `production` доступны секреты `DEPLOY_SSH_PRIVATE_KEY_B64` и
  `DEPLOY_KNOWN_HOSTS`.
- [x] CI после build, Trivy, smoke и публикации `latest` запускает deploy job.
- [ ] На хосте PHP-контейнер запущен из образа с SHA релиза и `/health` отвечает.
- [x] `bakery.css` после релиза соответствует содержимому образа.
- [ ] `laravel-app_postgres_data` остаётся подключённым к тому же PostgreSQL;
  рабочие данные и входы доступны.
- [x] Старый неиспользуемый PHP-образ удалён либо зафиксирована причина, по
  которой Docker оставил его.
- [ ] Deploy job завершается успешно с автоматической очисткой образов после
  ожидания готовности PHP.
- [ ] Релиз поднимает все сервисы из `/opt/bakery` после удаления контейнеров;
  на хосте нет checkout и `.env`.

Перед изменением релиза 2026-11-01 сделан проверенный `pg_dump -Fc`:
`/root/bakery-backups/bakery-20261101T052048Z.dump` на хосте и копия
`C:\Users\user\AppData\Local\Temp\bakery-20261101T052048Z.dump` на этом ПК;
SHA-256 обеих копий совпадает. `pg_restore -l` прошёл; пробное восстановление
ещё не выполнялось.
