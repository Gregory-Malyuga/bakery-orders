# ADR-0011 — Единый стек Caddy, PHP, PostgreSQL

**Status:** accepted

## Context

Для сайта пекарни локальный Compose содержал Redis, Elasticsearch, Mailpit, отдельный worker и scheduler, а рабочий Compose уже использовал только Caddy, PHP и PostgreSQL. Это давало разные пути выполнения сессий, кеша и очереди. Поиск пользователей в рабочем API не должен требовать отдельного поискового сервиса.

## Decision

- Использовать один `docker-compose.yml` с Caddy, PHP и PostgreSQL для локального и рабочего окружений.
- Хранить сессии и кеш в PostgreSQL; задачи очереди выполнять синхронно; письма писать в лог.
- Искать пользователей запросами к PostgreSQL и проверять в `/health` только БД.
- Удалить интеграции Elasticsearch и Redis из кода приложения, конфигурации и прямых зависимостей Composer. Mailpit не запускать.

## Consequences

Поиск по почте остаётся регистронезависимым, но больше не использует семантику Elasticsearch. Синхронная задача выполняется в рамках запроса; при появлении долгих фоновых задач понадобится отдельное решение для очереди. Для локального изменения PHP-кода требуется пересборка образа. Старые тома Redis и Elasticsearch не удаляются автоматически.

Это решение заменяет [ADR-0008](0008-async-elasticsearch-sync.md).
