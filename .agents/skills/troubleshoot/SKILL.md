# Диагностика сбоя в bakery-orders

1. Записать наблюдаемый симптом, среду и шаги воспроизведения. Открыть `docs/history/checklist.md` только для поиска похожего паттерна; совпадение ещё не доказывает причину.
2. Проверить текущее состояние кода и данных безопасным способом. Для финансового расхождения сопоставить исходный заказ, действующие возвраты, административную страницу, печать и XLSX. Для упавшего теста сначала повторить конкретный тест, затем связанный набор; использовать отдельную тестовую БД.
3. Отделить подтверждённые факты от гипотез. Установить причину по коду, тесту, журналу или измерению; исправить в рамках задачи и проверить пользовательский результат.
4. Если дефект остаётся открытым, завести `BUG-XX` в `docs/process/roadmap.md` по `docs/process/bug-template.md` и записать влияние. Если причина установлена и исправление проверено, создать `HIST-NNN.md` и добавить признак в `docs/history/checklist.md`. Не помещать открытый баг в историю как закрытый инцидент.

Подробный порядок и требования к отчёту: `docs/process/work-items.md`. PHP/Artisan/Composer запускать в контейнере `php`, когда он доступен; недоступные проверки обозначать явно. Доступ к production для чтения не подменяет разрешение на изменение данных.
