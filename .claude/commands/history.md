# /history

Зафиксировать **разобранный** неожиданный сбой или паттерн в `docs/history/`. Открытый дефект продукта сначала записывается как `BUG-XX` в roadmap; неизвестную причину не выдавать за установленную. См. [процесс](../../docs/process/work-items.md).

## Шаги

1. Найти максимальный номер среди файлов `docs/history/HIST-*.md` и взять следующий.
2. Создать отдельный файл `docs/history/HIST-NNN.md` по шаблону ниже. Указать ID связанной задачи/бага, если есть.
3. Добавить ссылку на файл в `docs/history/index.md` и строку-паттерн в `docs/history/checklist.md`.

## Шаблон записи

```markdown
# HIST-00N — <краткое название>

**Дата:** YYYY-MM-DD
**Связанная задача:** BAK-XX / BUG-XX, если есть.
**Контекст:** Что делали, когда произошло.
**Симптом:** Что именно упало / повело себя неожиданно.
**Причина:** Установленная причина и подтверждающее наблюдение.
**Фикс:** Что изменили и как проверили устранение.
**Паттерн для checklist:** <строка для docs/history/checklist.md>
```

## Строка в checklist

Добавить в таблицу `docs/history/checklist.md`:

```markdown
| <Паттерн в 3-5 словах> | [HIST-00N](HIST-00N.md) |
```
