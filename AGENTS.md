# Работа с задачами в bakery-orders

- Перед новой задачей прочитать `docs/state.md`, текущую очередь `docs/process/roadmap.md`, подробную постановку нужного ID и последние коммиты (`git log -10`). Архивный roadmap не считать текущей очередью.
- Процесс ведения задач и ошибок: `docs/process/work-items.md`. Открытый дефект записывать в roadmap с симптомом и способом воспроизведения; `docs/history/` использовать для сбоя с установленной причиной и проверенным исправлением.
- При неожиданном сбое сверить симптом с `docs/history/checklist.md` и использовать проектный навык `.agents/skills/troubleshoot/SKILL.md`. Навыки OEM и старые примеры Suggester сюда не переносить.
- После реализации обновлять статус только по выполненным критериям приёмки. Указывать фактически выполненные проверки и отдельно различать локальный коммит, push, CI и production-деплой.
- Сохранять несвязанные изменения в рабочем дереве. Работать с этого ПК; локальный коммит не означает push или production-деплой.
- Для изменений кода обязательно запускать проверки локально на этом ПК в Docker: перед коммитом — `composer pre-commit`, перед коммитом и перед push — полный `composer pre-push` (он включает тесты). Использовать отдельную тестовую БД по инструкции в `README.md`; успешный CI не заменяет локальный прогон. При недоступном Docker или провале проверки не считать её пройденной и не коммитить либо отправлять изменения кода. Для правок только документации проверять diff и ссылки согласно `docs/process/work-items.md`.
